# KERDOS catalog workflow — September 25, 2026

## Agreed behavior

1. Import the whole price sheet and retain its source. An ambiguous price-sheet row can enter the catalog with its quote held for review; other rows continue. Document-type conflicts and invoice checks retain their existing controls.
2. **New or unfinished item:** determine its category, retain the full vendor row, and assign or match a client KERDOS item. The client can correct individual fields and choose an association. Category alone does not prove product identity.
3. **Confirmed item:** locate it by organization, vendor, and vendor item number. Keep its KERDOS number and saved description, brand and pack. A price-only update does not repeat product matching or create a new item.
4. **Oversight:** compare supplied fields with the last accepted source after finding the saved link. Changed wording, brand, pack, quoted unit, barcode or manufacturer code is flagged. Keep the previous quote while the incoming quote is reviewed. Omitted fields on a code-and-price sheet use saved values. Formatting changes alone are ignored. An unapproved source never becomes the accepted baseline just because it was uploaded again.
5. **Full match:** shared price comparisons require compatible product identity, brand, purchasing pack and any supplied identifiers. Different brands or packs remain separate or in review. Vendor names and vendor item numbers can differ; comparison prices are normalized to the same purchasing pack.

## Item Catalog

Default table order: KERDOS item number; vendor; category; product; brand; pack; quoted amount; quoted per; calculated unit cost. Vendor item number is shown under the KERDOS number.

Column headers sort the table. Category and quoted unit have dropdowns. Product, brand, pack and quoted amount are editable. Pack details offer inner count, each size and measurement. Unit choices share base measurements and the organization's vocabulary. Missing brand remains blank. Each cell has its own evidence/status percentage; these are not measured accuracy probabilities.

Save row can save partial progress. The database saves the affected category, vendor fields, review status and any quote history together. A stale edit is rejected instead of overwriting a newer save. Details expose original source, field reasons, incoming changes and the existing association controls. A correction to defining product fields retains the link but asks for verification before that offer competes.

## Retained gains

The existing Product details view, vendor association selection, vendor price ranking and differences, negotiated prices, ordering controls, price validity settings and invoice history remain. The blue interface is retained. Changes do not delete client data or reset established item numbers.
